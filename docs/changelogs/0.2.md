# 0.2.x

## 0.2.0 — 2026-10-01

### Added

- A dedicated `mobile` build target and `mobile` platform adapter, used by the Naigi mobile app. It reuses the existing pages, encryption, and voice code instead of porting the desktop interface.
- A phone-native chat layout: one full-screen column with the room drawer as the only navigation surface, opened on demand.
- A full-screen room drawer for phones: server identity, spaces with their rooms, a room search field, and the account bar pinned to the bottom.
- A composer pill with a plus on the left and emoji and GIF controls on the right. A sheet opens directly under the composer:
  - **Media** shows a four-column thumbnail grid of everything queued for the message, with a **Photos** and **Files** action row.
  - **Emoji** and **GIFs** share one panel with a tab for each, a search field, and grids sized for touch instead of hover.
  - While a sheet is open the composer swaps its send button for a close control.
- Larger touch targets throughout the mobile layout: 44px minimum for composer, header, and drawer controls, 48px for room rows and server selection, plus safe-area insets for notches and the home indicator.
- Touch-friendly fallbacks so hover-only affordances (message actions, media actions) stay visible on devices without hover.

### Fixed

- Icons used by the chat page render again, including the image, radio, and user glyphs that were missing from the icon set.
- The mobile composer no longer inflates when a long placeholder wraps in a narrow field; the field is capped and scrolls instead.
- Mobile sheet controls take precedence over the desktop popover toggles, so a panel no longer closes itself immediately after opening.

### Changed

- The mobile app opens on the conversation with the drawer closed, instead of landing on an open sidebar.
- The mobile header drops the notification bell and lock controls, which belong to push delivery and settings, and keeps navigation, search, and conversation details.

### Security

- The mobile platform adapter accepts only HTTPS server origins, matching the app shells' cleartext-traffic policy, and never falls back to an unconfigured server.
