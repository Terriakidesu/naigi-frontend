# 0.3.x

## 0.3.0 — 2026-10-08

Room content markers: a warning before an adult-content room opens, and a room that spoils everything in it.

### Added

- **Adult-content rooms.** A room can be marked as adult content by someone who manages rooms. Opening one shows a warning first and loads nothing until you choose to continue, so nothing in the room is fetched, decrypted, or rendered while the decision is being made. The warning starts focused on the way out, and Escape goes back rather than through. Continuing is remembered per room on that device, so the room stops asking; it is never sent to the server and never affects anyone else in the room. Refusing leaves you exactly where you were, including the room you were reading.
- **Adult-content marks in the room list.** Marked rooms carry a small mark and say so in their accessible name, because the warning is only useful if you can tell which room it applies to before opening it.
- **Spoiler rooms.** A room can be marked as a spoiler room, which conceals everything posted in it: message bodies, quoted replies, images and video behind the existing blurred previews, file names, and decrypted text-file previews. Sender names and timestamps stay visible, and each concealed item is revealed on its own, by click or keyboard. Nothing is removed from the page, so revealing is reversible and the text stays selectable afterwards.
- Two checkboxes for these markers on each room's row in space settings, shown to members who manage rooms. They require the same permission server-side, and are deliberately not part of the room-editing bundle.
- Attachments queued in a spoiler room are marked as spoilers when they are sent, not only when they are rendered, so a client that does not know about the room still blurs them. Text is not rewritten: wrapping it in `||spoilers||` would change what people copy out of the room, so message text is concealed on the reading side only.

### Changed

- Both markers are read from the room itself rather than the encrypted room metadata. A member added to a room after its metadata was written may never be able to decrypt it, and a warning hidden in ciphertext would fail open. A marker missing from a room is treated as off, so a server that does not send them changes nothing.

### Known gaps

- A spoiler room conceals what the room renders. It cannot conceal text that is already on the device: copying a message, and a browser's own find-in-page, still work on content you have revealed.
- Voice rooms show the adult-content mark but are never blocked, because they hold no message content to conceal.
